# StockLab

**실시간 모의투자 웹 대시보드 & 가상 체결 시뮬레이터**

> 손실의 두려움 없이 실전 시장 데이터를 기반으로 투자 전략을 검증·복기할 수 있는 실시간 모의투자 플랫폼

---

## 1. 프로젝트 개요 및 기획 목적

* **기획 배경**:
  * 개인 투자자가 실전 투자를 망설이거나 조급한 매매로 실패하는 핵심 원인은 **원금 손실에 대한 심리적 압박**에서 비롯됩니다.
  * 실제 한국·미국 시장 시세와 호가 데이터를 기반으로 원금 손실 없이 실전과 동일한 주문·체결·정산 흐름을 경험하고, 차분하게 차트·거시 경제·매매 내역을 복기할 수 있는 모의투자 플랫폼을 목표로 설계했습니다.
* **접근성 및 도메인 목표**:
  * 무거운 기존 HTS/MTS 대신 직관적인 반응형 **웹 대시보드**와 추후 **Discord 봇 연동**을 결합해 언제 어디서나 가볍게 접근할 수 있는 환경을 지향합니다.
* **금융 백엔드 3대 핵심 도전 과제**:
  * **원장 데이터 무결성**: 단 1원의 잔고 오차나 체결 순서 왜곡도 허용하지 않는 엄격한 트랜잭션·동시성 제어
  * **초저지연 및 고효율 I/O**: 대량의 정적 마스터·실시간 호가·미체결 주문 데이터를 GC 압박과 DB 병목 없이 처리하는 인메모리 아키텍처
  * **외부 API 유량 제약 방어**: 초당 호출 제한(TPS)과 동시 연결 슬롯 제약이 엄격한 증권사 OpenAPI 환경에서의 안정적 캐싱·유량 제어

* ✅ **실시간 WebSocket 호가 스트리밍 + REST 스냅샷 하이브리드 시세 파이프라인**
  * 실시간 호가 WebSocket 수신 및 SignalR Fan-Out 브로드캐스트, 2중 하이브리드 상세 시세 모달(실시간 호가 + 쿨다운 기반 REST 스냅샷) 구축
* ✅ **비관적 행 락 기반 FIFO·호가 잔량 10% 유동성 분할 체결 엔진 및 인메모리 미체결 캐시**
  * 가격-시간 우선(FIFO) 체결, 호가 잔량 10% 유동성 한도 분할 체결, 시장가 예약금 불변 정산 및 인메모리 호가 버킷 캐시 기반 초저지연 매칭 필터링
* ✅ **6대 채널 분리 파일 로깅 및 관리자 관제 시스템**
  * 성격별 6개 채널 분리 로거(메인·외부 API 유량·거래·관리자·SQL·디버그) 및 10MB 단위 자동 롤링
  * 관리자 대시보드: 서버 사이드 페이징, SignalR 실시간 동기화, 미체결 5대 대기 사유 런타임 진단, 장외 테스트용 강제 체결 스위치, 대기 주문 일괄 취소 및 더미 트래픽 부하 시뮬레이터
* ✅ **무손실 스키마 마이그레이션 체계 전환**
  * 기존 운영/개발 데이터를 100% 보존하면서 기준점을 자동 등록하고 증분 스키마 업데이트를 누적 적용하는 마이그레이션 파이프라인 완비
* ✅ **공통 모듈·백엔드·로컬 클라이언트 3계층 물리 분리 (`Shared` / `Server` / `Client`)**
  * 공통 시세·마스터·로깅·실시간 허브 모듈을 공용 라이브러리(`Shared`)로 분리해 중앙 원장·체결 서버(`Server`)와 독립 웹 클라이언트(`Client`) 간 코드 중복을 제거하고 책임을 명확히 분리
  * `Client`가 사용자 개인 KIS API 키(클라이언트 전용 환경변수 우선 지원)와 초당 18회 유량 제한기를 적용해 증권사 시세·호가 스트리밍을 직접 호출·제공(동일 출처 시세 API 및 실시간 허브)하며, `Server`는 엄격한 CORS 정책 하에 중앙 계정·원장·체결 API를 담당

  | 프로젝트 | 역할 및 책임 |
  |---|---|
  | **`Shared`** | 공용 시세·종목 마스터·유량 제한·채널별 파일 로거·예외 처리·실시간 허브 라이브러리 |
  | **`Server`** | 중앙 PostgreSQL 원장·계정/인증·주문/체결 엔진·관리자 관제 API 및 실시간 주문 알림 서버 |
  | **`Client`** | 웹 UI(`Dashboard`·`User`·`Admin`) 호스팅, 개인 KIS 키 기반 직접 시세/호가 스트리밍, 클라이언트 독립 파일 로깅 |

## 4. 핵심 엔지니어링 성과 및 트러블슈팅 하이라이트

### 1) 상시 DB 폴링 제거를 통한 초저지연 인메모리 매칭 필터링
* **문제**: `500ms` 호가 폴링 워커, `333ms` 강제 체결 워커, 매 호가 틱 처리기에서 반복 실행되던 미체결 주문 DB 조회(일 `172,800회` 이상)가 유휴 시간대에도 DB 커넥션과 디스크 I/O를 지속적으로 소모했습니다.
* **해결**: 종목·호가 가격 레벨 단위의 인메모리 호가 버킷 캐시(주문 ID 역인덱스, 동기화 중 변경 재적용 버퍼, 1분 TTL 종료 주문 재등록 차단)를 구축하고, DB 전체 스냅샷 로드는 서버 기동 및 국내·해외 장 개장/마감 전환 시점에만 실행하도록 전환했습니다.
* **성과**:
  * 상시 폴링 DB 조회를 **일 172,800회 → 기동·장 전환 시 1+최대 4회**(99.997% 절감)로 축소하고, **유휴·쿨다운 구간 DB 커넥션·쿼리를 0회**로 제거했습니다.
  * `.NET 10 Release` 실측 기준 **10,000건(200종목) 적재 시 메모리를 `~3.22 MB`만 점유**하며, **사전 매칭 판별 `40.0 ~ 871.5 ns`(힙 할당 `0 B`)**, **단건 추가·제거 왕복 `711.8 ns`를 기록**해 로컬 PostgreSQL **단순 쿼리(`1~8 ms`) 대비 약 93배 ~ 28,409배** 지연 시간을 단축했습니다.

### 2) ORM 변경 감지 $O(N^2)$ 병목 & 불필요 트랜잭션 제거
* **문제**: 디버그 로깅 개방 직후 3분간 `14.6 MB`(10만 줄 이상)의 로그가 폭증한 장애를 추적한 결과, 체결 루프 내부의 로컬 캐시 반복 조회로 인한 ORM 변경 감지 $O(N^2)$ 호출, 동일 컨텍스트 연속 사용 시 낙관적 동시성 토큰 충돌, 미매칭 호가 틱마다 3개 테이블 배타적 행 락을 잡았다가 롤백하는 오버헤드가 확인되었습니다.
* **해결**: 선점 엔티티를 메모리 딕셔너리로 직접 전달하고 매칭 루프 구간 동안 ORM 자동 변경 감지를 일시 비활성화해 배치당 단 1회만 수행되도록 개선했습니다. 또한 트랜잭션 직전 컨텍스트 초기화, 매칭 가능 여부 선행 필터링, 로거 2중 에코 제거 및 감사 SQL 쓰기/DDL 선별 필터링을 적용했습니다.
* **성과**: 매칭 루프 내 변경 감지 비용을 $O(N^2)$에서 **배치당 `1회`로** 줄이고, 미매칭 호가 틱의 **3중 행 락 진입을 `0회`**로 차단했으며, 감사 SQL 로그를 **쓰기·스키마 제어 명령 중심(`234 → 4건`)으로 정밀화**했습니다.

### 3) 병렬 체결 교착 상태 해소 및 원장 예수금 무결성 보장
* **문제**: 다중 종목을 병렬 체결할 때 서로 다른 트랜잭션이 시나리오 지갑 행을 엇갈린 순서로 잠그면서 DB 교착 상태(Deadlock)가 발생했고, 호가 급등 시 시장가 매수 주문이 최초 예약 예산을 초과해 가용 현금을 추가 인출하는 원장 결함이 식별되었습니다.
* **해결**: 트랜잭션 진입 시 연관 시나리오 ID를 오름차순으로 정렬해 일괄 배타적 행 락을 선점하는 **락 순서 정규화(Canonical Lock Ordering)를 적용**하고, 시장가 주문의 최초 예약 총액 불변 원칙과 잔여 예약금 한도 내 부분 체결·잔여 수량 거절 환불 정산 로직을 확립했습니다.
* **성과**: 잠금 왕복 쿼리를 **`2N → 2회`**로 감축하고, **1,050건 주문 + 60모의틱 병렬 부하 테스트에서 Deadlock 0건·불변량 위반 0건**을 검증했으며, `+8% ~ +25%` 호가 급등 재테스트에서 시장가 잔여 거절(**`253건`**) 및 환불 정산 무결성을 확인했습니다.

### 4) 캐시 스탬피드(`10.56초` 블로킹) & 모달 지연(`6~11초`) 해소
* **문제**: TTL 만료 시 기존 캐시를 먼저 삭제하고 요청 스레드가 외부 API 응답을 동기 대기하던 구조 때문에, 60초 만료 직후 **`10.56초` 블로킹**, 클라이언트 취소에 따른 연쇄 예외 및 화면 데이터 증발, 모달 상세 시세 조회 **`6~11초` 지연**, 해외 API 절대값 등락폭으로 인한 부호 충돌이 발생했습니다.
* **해결**: 만료 시에도 다음 유효 값을 받아올 때까지 기존 값을 **`0 ms`로 즉시 반환**하고 백그라운드 단일 태스크로 원자적 교체하는 **유지 후 교체(Retain-Until-Replaced)** 아키텍처로 전환했습니다. 아울러 인기 순위 상위 20종목 시세의 **인메모리 선적재(Warm-up)**, `finally` 기반 폴링 쿨다운 보장, 기준가 가상 호가 폴백 및 등락 부호 정규화를 적용했습니다.
* **성과**: 캐시 적중 시 **`0 ms` 즉시 응답**을 확보하고, 백그라운드 격리 타임아웃(`15초`/`10초`)·콜드 스타트 타임버짓(`2초`)·실패 백오프(`30초`)로 캐시 스탬피드와 연쇄 취소 예외를 원천 차단했습니다.

### 5) 외부 API 초당 18회 유량 제어 & WebSocket 41슬롯 누수 방어
* **문제**: 증권사 OpenAPI의 엄격한 초당 호출 제한(TPS)과 WebSocket 세션당 41슬롯 한도 속에서, 초기 **1초 주기 REST 폴링** 요청의 `70%` 이상이 중복 캐시 적중으로 버려졌고, 단일 미체결 종목 폴링 시 분당 `120회` 호출 및 단순 정수 카운터 기반 WebSocket 열람 인원 누수(유령 클라이언트) 문제가 발생했습니다.
* **해결**: 30종목 청크 일괄 조회 설계와 함께 REST 폴링을 과감히 철회하고 이벤트 기반 __WebSocket(41슬롯) + SignalR__ 구조로 피벗했습니다. 프로세스 전역 **초당 `18회` 고정창 유량 제한기**(FIFO 대기열)와 종목별 **`5초` 쿨다운**, **연결 ID 양방향 집합 역인덱스·연결 종료 자동 회수** 및 모달 닫힘 레이스 컨디션 가드, 외부 API 전용 로그 채널을 구축했습니다.
* **성과**: 일괄 시세 호출 네트워크 I/O **96%(`1/30`) 절감**, 단일 종목 폴링 호출량 **90%+ 감축(분당 `120회 → 12회` 이하)**, 18 TPS 백프레셔 실시간 추적 및 WebSocket 연결 자동 해제를 달성했습니다.

### 6) 운영 DB 무손실 마이그레이션 전환
* **문제**: 초기 스키마 생성 전용 방식으로는 잦은 컬럼/인덱스 추가에 대응할 수 없었으며, 기존 DB에 마이그레이션 이력 테이블이 부재한 상태에서 단순 전환 시 테이블 중복 충돌과 이력 확인 오판 예외가 발생했습니다.
* **해결**: 오프라인 디자인 타임 컨텍스트 분리 및 로컬 CLI 도구 버전 고정을 수행하고, 기존 테이블 실존 여부를 데이터베이스 메타데이터 파라미터화 조회로 정확히 판별해 이력 테이블 생성과 기준점 등록을 트랜잭션 내에서 자동 수행하는 무손실 전환 로직을 구현했습니다.
* **성과**: 기존 운영/개발 **데이터를 `100%` 보존**한 채 증분 마이그레이션 체계로 전환하고, 서버 재기동 시 **마이그레이션 오류 로그 `0건`을 검증**했습니다.

### 7) 대용량 바이너리 마스터 Zero-Copy 파싱 & 락-프리 무중단 교체
* **문제**: 약 `744 KB`(`2,576건`) 고정 길이 바이너리 마스터 파일을 행 단위 문자열 분할로 파싱할 때 루프당 최소 **`15,000개+`의 단기 힙 객체**가 생성되었고, 일중 `13회` 배포 갱신 중 조회 데이터 공백·배타적 락 병목 및 새벽 재기동 시 당일 첫 배포 스킵 엣지 케이스가 존재했습니다.
* **해결**: CP949 인코딩 비동기 일괄 로드 + **Zero-Copy 바이트 슬라이싱(288바이트 레코드 오프셋 직접 디코딩)**, **메모리 배리어 기반 락-프리(Lock-Free) 원자적 참조 교체**, 그리고 조건부 HTTP 요청(`If-Modified-Since`) 및 직전 유효 배포 시각 역산 알고리즘을 구현했습니다.
* **성과**: 마스터 전량을 **수 밀리초(ms)** 내 힙 낭비 없이 파싱하고, 갱신 중 조회 **대기 0초(Zero-Downtime)** 및 무변경 배포 시 **`304 Not Modified`(`0 B / 0초` 스킵)** 처리를 달성했습니다.

## 6. 실행 및 환경변수 설정 안내

본 저장소는 보안 원칙에 따라 **어떠한 API 키, DB 비밀번호, 인증 토큰, 로컬 시크릿 파일도 포함하지 않습니다.** 로컬 실행을 위해서는 아래 외부 자격 증명을 별도로 주입해야 합니다.

1. **사전 준비물**:
   * .NET 10 SDK
   * PostgreSQL 18 (대상 데이터베이스 생성 필요)
   * 한국투자증권(KIS) OpenAPI 계좌 및 `AppKey` / `AppSecret`
2. **외부 시크릿 분리 주입**:
   * **OS 환경변수**: KIS OpenAPI `AppKey` / `AppSecret` 설정 (폴백 없음 — 사용자 로컬 키 미설정 시 클라이언트 접근 전면 제한)
   * **.NET User Secrets**: PostgreSQL 연결 문자열 및 관리자 인증 키 설정 (`dotnet user-secrets` 활용)
3. **도구 복원 및 실행**:
   ```powershell
   dotnet restore
   dotnet tool restore
   dotnet run --project Server   # 중앙 API 및 주문·체결 원장 서버
   dotnet run --project Client   # 웹 UI 및 직접 시세·호가 클라이언트 (별도 터미널에서 Server와 동시 실행)
   ```
   * `Server` 기동 시 데이터베이스 마이그레이션 자동 점검·적용 및 글로벌 종목 마스터 메모리 적재가 수행되며, `Client`는 자체 종목 마스터·시세·실시간 호가 스트리밍과 함께 웹 대시보드(`/`)·내 페이지(`/user`)·관리자 관제 페이지(`/admin`)를 활성화합니다.
